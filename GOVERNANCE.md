# Project Governance

## Overview

The Fahrenheit Temperature Converter is a **first-party website project** - a personal tool developed and maintained by Ali Sajid Imami. The project follows a **Benevolent Dictator** governance model and is open source for transparency and educational purposes.

This document outlines the decision-making process, roles, and responsibilities within the project.

## Governance Model

### Benevolent Dictator

The project is led by **Ali Sajid Imami** ([@AliSajid](https://github.com/AliSajid)), who serves as the project maintainer and has final authority over all project decisions, including:

- Technical direction and architecture
- Feature acceptance and prioritization
- Release scheduling and versioning
- Contributor role assignments
- Code of Conduct enforcement
- Security policy and response
- License and legal matters

### Decision-Making Process

1. **Open Discussion**: Most decisions begin with open discussion in GitHub Issues or Discussions
2. **Community Input**: Contributors are encouraged to provide input and feedback
3. **Consensus Building**: Effort is made to reach consensus when possible
4. **Final Authority**: The project maintainer makes final decisions when consensus cannot be reached

## Roles and Responsibilities

### Project Maintainer

**Current**: Ali Sajid Imami ([@AliSajid](https://github.com/AliSajid))

**Responsibilities**:

- Set project vision and roadmap
- Review and merge pull requests
- Manage releases and versioning
- Enforce Code of Conduct
- Respond to security issues
- Maintain project infrastructure
- Mentor contributors
- Grant contributor roles

### Contributors

**How to Become a Contributor**:

- Submit pull requests that are accepted
- Participate in issue discussions
- Help with documentation
- Report bugs and suggest features

**Responsibilities**:

- Follow the [Code of Conduct](CODE_OF_CONDUCT.md)
- Adhere to [Contributing Guidelines](CONTRIBUTING.md)
- Use conventional commits
- Write tests for code changes
- Maintain code quality standards

### Core Contributors (Future)

As the project grows, core contributors may be designated with additional responsibilities:

- Review pull requests
- Triage issues
- Mentor new contributors
- Participate in roadmap planning

**Selection Criteria**:

- Consistent, high-quality contributions
- Deep understanding of the codebase
- Adherence to project values
- Community engagement

## Communication Channels

- **GitHub Issues**: Bug reports, feature requests, task tracking
- **GitHub Discussions**: General questions, ideas, community interaction
- **Pull Requests**: Code reviews and technical discussions
- **Email**: Security issues, Code of Conduct violations, private matters

## Conflict Resolution

1. **Discussion**: Address conflicts openly and respectfully
2. **Mediation**: The project maintainer may mediate disputes
3. **Final Decision**: The project maintainer has final authority to resolve conflicts
4. **Code of Conduct**: Serious violations may result in temporary or permanent bans

## Changing Governance

This governance model may evolve as the project grows. Changes to governance will be:

- Proposed by the project maintainer
- Discussed openly with the community
- Documented in this file with clear version history
- Announced to all contributors

## Future Governance Evolution

As a first-party website project, governance is expected to remain with the project owner. However, if circumstances change:

- **Additional Maintainers**: Trusted contributors may be granted maintenance access
- **Code Stewardship**: If the project is transferred, governance will be documented accordingly

Given the project's nature as a personal website tool, community governance models (committees, voting, foundation hosting) are not anticipated.
